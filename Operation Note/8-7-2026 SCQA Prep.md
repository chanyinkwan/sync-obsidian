## 教練筆記 — 會議流程與重新框架（2026-07-06 加入）

**會議流程（15 分鐘）— 先講「他要聽的」：**
1. **0–1 · 開場定調：** 「先講你要的三項,再分享兩個觀察 + 我想發展的方向。」
2. **1–6 · 他的議程(先講結論):** 樣機盤點(+ 我需要你拍板的 1 個決定) → 聯絡人(影響力地圖 + 我下一個要經營的關係) → 產品(理解的成長軌跡 + 1 個具體例子)。
3. **6–8 · 價值證明:** 已解決的問題(stock alignment)—— 量化「避免了什麼風險」。
4. **8–12 · 核心提案(務必保住這段):** 痛點 → 問題+解方 → 「Feasible or Not?」。
5. **12–14 · 發展意向:** 先表忠誠再談野心(「先把 ops 做到自動運轉 → 再爭取進 sales/strategic」)。
6. **14–15 · 收尾:** 確認拍板的決定。
- *若時間不夠:* 產品壓成 1 句;到期問題併成「下次再細講」;發展意向留成「下次 check-in 的種子」。**絕不砍**:那個決定 + Feasible 提問。

**重新框架(避開隱形摩擦):**
- **「Ops 太重 / Sales-Strategic 太輕」** → 不是抱怨。改說:*「這角色目前約 80% 是 ops;我的規劃是先用追蹤系統把 ops 去風險化,再把騰出的產能投入 sales/strategic —— 你希望我怎麼往那邊建立?」*
- **痛點** → 先肯定現狀(Situation),以「新人視角、可能漏了脈絡」自我定位,用「True or Not?」邀請他給看法。不要講成「我們的溝通很爛」。
- **發展意向** → 一律「先承諾、對內成長」框架(對外求職的事絕不帶進這個房間)。

**問題 + 解方腳本:**
- **溝通 / 重複工:** *問題* — 樣機狀態靠人傳人 `H→H→Record→H→H`,紀錄滯後、工作重做(重印、寄錯人)。 *解方* — 結構化收件(MS Form / 標準郵件模板)→ `H→Record→H`,單一真相來源。 *提問(Feasible?)* — 「以 IT/security 限制來看可行嗎?我用留白時間先試點,兩週後回報。」
- **到期缺口:** *問題* — 到期日靠非正式追蹤,有逾期風險(尤其義大利)。 *解方* — 每月掃一遍 + 提前一個月核銷/延期。 *提問(True?)* — 「逾期在真實業務裡是真風險嗎?還是有我沒看到的安全網?」
